# Phase 4, steps 4A and 4X: delivered data on three pages, and one command

Date: 2026-11-15. Drafted by an architect agent for the roadmap coordinator from the deadline
brief (`deadline-brief-2026-11-16.md` in the shared notes folder), the roadmap, the 3A and 3B
plans and the code on `origin/main` at `4df574a1`. Open pull requests were read at their heads
on 2026-11-15 (numbers below). Legacy was read at `legacy/main` `9d040f81` with `git show`,
never checked out. Steps 4B to 4D are not in this plan.

**Goal:** one command takes a synthetic issuer's source folder through a run on the canned
provider and writes a library folder that opens from disk in Chrome and Edge, with Library home,
Report history and Overview showing that run's data.

**Reader:** a portfolio manager or credit committee member who has not read the sources. They
open `index.html` from a folder. They see judgement first; a source name, a file, a page or a
hash only on Evidence and in the trace control.

**What this plan does not do:** build or restyle a page (roadmap, "Pages are built once");
add analysis or arithmetic outside `model/`; parse Markdown outside `handoff/`; call a paid
provider or import the Copilot SDK; write a workbook; change the content security policy
(`web/index.html:5-8`); wire Modules, Forecast, Evidence, Changes or the Run pages; package the
application for the work PC (phase 7).

**Ends in:** six pull requests against `main`, one per row of "PR sequence", no size split
(decision 0015, open as #438). Whole-branch review once per step.

**Sensitive code:** ordering in 4X-1 (the order in which front-end files, downloads and
`data.js` reach the folder). No money code is added: prices, holds and spend stay in
`orchestrator/` and `delivery/`.

## Step 4X: one command

### The entry module

**Name:** `credit_os.launch`, a sub-package: `launch/__init__.py`, `launch/__main__.py`,
`launch/cli.py` (arguments, exit codes, printing), `launch/assemble.py` (the front-end copy),
`launch/run.py` (the sequence). `python -m credit_os.launch` starts it, as
`src/credit_os/signal/__main__.py` starts Signal. It cannot be a root module (P16).

**Layer:** `LAYERS` becomes `sources`, `handoff`, `model`, `provider`, `store`, `checks`,
`orchestrator`, `delivery`, `launch`, `signal` (`src/credit_os/__init__.py:5-15`). `launch`
imports the eight before it and never `signal`; nothing imports `launch`.

**Layering test change:**

- `src/credit_os/__init__.py` and the pinned tuple in `tests/test_package.py:11-21` gain
  `launch` between `delivery` and `signal`. The pin is an answer key: the controller edits it.
- `tests/test_layering.py` gains rows built with its `_tree` helper: `delivery` and
  `orchestrator` importing `launch` are violations (absolute, relative and
  `importlib.import_module`); `launch` importing `delivery` and `orchestrator` is allowed;
  `launch` importing `signal` is a violation.
- New `tests/launch/test_launch_imports.py` reads the syntax tree of every file in
  `src/credit_os/launch/`: from `credit_os.provider` only `canned` and `types` are imported; no
  `copilot` name and no `subprocess` is imported; no call to `rmtree`, `unlink`, `remove` or
  `rmdir`.

### The command's arguments

All but `--modules` are required; nothing has a default path. There is no `--live`: this
command constructs `CannedModel` only, and a paid run stays the owner's separate action.

| Argument | Meaning | Refused (exit 2, nothing stored) when |
| :--- | :--- | :--- |
| `--sources <folder>` | The issuer's source folder | Not a folder; over the launch caps (#400) |
| `--context <file>` | The `context/1` JSON (`orchestrator/context.py:717`) | `ContextRefused` |
| `--recording <file>` | The canned recording, JSON Lines (`provider/canned.py:70`) | `RecordingError` |
| `--methods <folder>` | One UTF-8 file `<module id>.md` per module (P10) | A planned module has no file |
| `--run-id <id>` | The run's id, `[A-Za-z0-9._-]{1,128}` (`delivery/names.py:56`, `:76-82`) | Outside the grammar; `.` or `..`; already in the store (P13) |
| `--cap <USD>` | The run cap, a decimal string | `LaunchRefused` (`orchestrator/prepare.py:93-94`, `:105-109`) |
| `--state <folder>` | Holds the store file and the delivered folders; made absolute first (P14) | The store refuses it |
| `--web <folder>` | The built front end (`web/dist`) | No `index.html`; a link; a `downloads` entry; a name outside the path rule; over 1,000 files or 64 MiB |
| `--library <folder>` | The folder to write; created when absent | A link or a file |
| `--modules <id ...>` | Optional; default the context's pathway | `LaunchRefused` |

Every refusal above is checked before `create_run`, so a refused command leaves no run.

Exit codes: 0, the run ended, was admitted, and `deliver` wrote it; 1, a run was created but
the library does not show it (the run ended `failed` or `stopped` with nothing admitted, or
`deliver` left it out or refused), with the rule printed; 2, refused before a run was created.
`launch` catches only the named classes (`LaunchRefused`, `ContextRefused`, `RecordingError`,
`SourceError`, `StoreError`, `DeliveryRefused`, `OSError` from the copy); anything else
propagates. No catch-all, no fail-open. A message shows the argument as typed or a shown name,
never a resolved path of another folder. The last line of a success names `index.html`.

**Invariants for review.** L1: at every point the library folder has no `index.html`, or one
whose referenced files are all in place. L2: only `deliver` writes `data.js` and `downloads/`.
