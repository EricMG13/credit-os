# 0015 Deadline mode until 2026-11-16 09:00 GMT

Date: 2026-11-15. Decided by: the owner, in conversation on 2026-11-15, recorded by the
coordinator. The rulings lapse at 2026-11-16 09:00 GMT.

## Why

The target is one command that takes a synthetic issuer's source folder through a run on the
canned provider and writes a library folder that opens from disk in Chrome and Edge (roadmap
step 4X, by the narrowest path). The full roadmap does not fit in the time left, and CI queue
time and the usage window are the bottleneck. These rulings relax global rules 1, 3 and 7.

## Decision

1. **The 800-line cap is lifted.** One PR per planned PR in each step's PR sequence; a planned
   PR is not split to fit a size. The "Changed lines at most 800" check in `review.yml` is not
   changed. Until the lapse, a red result of that one check alone does not block a merge of a
   Keep PR; every other check must be green.
2. **One review per PR.** `mx-precise` on each PR; `mx-adversary` only where the diff touches
   money or ordering code. The whole-branch review runs once per step.
3. **Non-roadmap sessions stop.** Signal, sweeps, records batches and design polish hold. Mutation
   runs are deferred past the deadline; each PR says so under `Not verified:`.
4. **CI load is cut.** PR 437 (main checked on a schedule, not on every merge) merges when green.
   Windows runs on a pull request only when it is not a draft: a step's intermediate PRs stay
   drafts and marking one ready starts the Windows leg (`ready_for_review` is a `pull_request`
   type in `python.yml` and `web.yml`). Windows always runs on schedule and on demand.
5. **Merges on green are pre-authorised for critical-path PRs.** A PR in the Keep list below
   may be merged without asking once its checks are green (item 1 excepted) and its
   one review has passed. This does not cover PRs outside the Keep table, paid runs,
   force-pushes or dependency additions; those stay with the owner.
6. **Adversarial hardening stops.** Owner's words, 2026-11-15, relayed by the
   development-performance session: 'stop adversarial hardening, tell the coordinators'. A planned
   PR is done when the roadmap's Delivers line for it works, its answer key passes and the gates
   exit 0. No new PR, slice, cap, guard or ruling is opened for a hostile or unusual input the
   roadmap line does not name; such findings are recorded and parked for one batch after phase 7,
   with the Low and Info findings, and do not reopen review. Still fixed now: a wrong figure, lost
   or corrupted data, a leaked secret or path, or a failure on the ordinary inputs the step exists
   to handle. Reviews under ruling 2 report against the delivered behaviour. Open hardening PRs
   (#423, #433, #434, #435) stay parked. This ruling removes no gate, allows no stub and permits no
   paid run.

Canned provider only; no live run. 1C (PR 3b tool-call turns, PR 4 the SDK binding) is deferred.
